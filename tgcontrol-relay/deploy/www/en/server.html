How it works

Three parts: your server, the Remotai agent on it and the remote control in your hands.

Your server

Any VPS from any provider - Linux, from one gigabyte of memory. Your CLI agents also live there: Claude Code, Codex, Kimi, Gemini, opencode.

Remotai agent on the server

Installed by one command and keeps the connection itself. Port forwarding, public IP address and firewall settings are not needed. A separate SSH client is also not needed: add the server to the application, click “Install Remotai”, and the server console will open right there.

curl -fsSL https://remotai.ru/install.sh | sh

Remote - phone or browser

Log in using the code that the agent showed in the console. Next - the terminal, files, screen and launching tasks from any device.

Frequently asked questions

Do I need my computer for this to work?

No. The agent and all your tools live on the server. A phone or browser is a remote control: it shows what is happening on the server and sends commands there.

Is Remotai a VPN?

No. Remotai doesn't change your network access and doesn't tunnel anything for you. This is a remote control for your own machine: you connect to your server and work on it.

My server is abroad - will the agent work there?

Yes. The agent works on the network of the server on which it is launched: if the service is available in its country, everything works normally, and you don’t need to configure anything on your phone or computer. Remotai does not interfere in this chain - it shows you the terminal of your machine and sends commands there.

What agents are supported?

Any console ones: Claude Code, Codex CLI, Kimi, Gemini CLI, opencode and everything that runs in the terminal. Remotai does not replace the agent - it gives him a workplace and you access to it.

How safe is it?

Keys and data remain on your server. The connection is encrypted, access to the machine is provided only by the binding code, and the device can be recalled at any time from the application.

What if the server reboots?

The agent gets up on his own and restores communication. Terminals with history are returned, unfinished tasks are visible in the list.
